# 技术愿景与开发规划（评审版）

> 本文档面向预算评审与技术尽调，阐述"完整形态"下的技术路线、动画管线、预算分配与交付标准。
> 当前仓库中的概念原型是这一愿景的**轻量验证**——只做外形与核心交互闭环，用于快速对齐价值；
> 完整方案待额度批准后按本文档落地。

---

## 0. 一句话方案

**UE5 + GAS + Control Rig 混合动画管线 + 数据驱动帧窗口 + 自定义判定/回放调试 + Pixel Streaming 试玩。**

预算高，但钱主要花在**可复现的弹反手感、高保真反馈和可扩展管线**上，而不是单纯堆美术。

---

## 1. 产品定位与评审策略

按最高档开发额度申请，Demo 规格直接拉到**"可对外评审的 PC 级垂直切片"**：

- **不**用 Phaser / Pixi 做网页原型；
- 主管线直接上 **Unreal Engine 5 + C++ / Gameplay Ability System**；
- 网页试玩用 **Pixel Streaming 云端串流**解决评审门槛；
- 保证**主战斗管线与最终产品一致**，不为网页端牺牲判定精度和表现力。

这样做的意义：评审者看到的就是最终产品的真实手感与表现，而非"另一套简化demo"，技术风险被前置消化。

---

## 2. 引擎与技术栈

| 领域 | 选型 | 用途 |
|---|---|---|
| 引擎 | Unreal Engine 5.4 / 5.5 | C++ 为主，蓝图做工具与调参 |
| 能力系统 | GAS (Gameplay Ability System) | 技能、状态、弹反窗口、霸体、取消规则 |
| 逻辑帧 | 固定 60 / 120Hz | 渲染插值，战斗判定与动画表现解耦 |
| 判定 | 自定义 hitbox / hurtbox 查询 | 不依赖物理引擎硬判，保证手感可控 |
| 音频 | Wwise | 打击、弹反、僵直、机甲液压/推进器分层音效 |
| 资产 | Houdini + Substance | 硬表面、破损、特效程序化生成 |
| 版本 | Perforce + 自动化构建 | 帧步进、判定盒可视化、输入回放、战斗日志 |
| 试玩 | Pixel Streaming（云）+ 桌面版（高保真） | 降低评审门槛，保留高保真评审路径 |

### 2.1 为什么是 GAS + 固定帧

- GAS 的 Ability / Effect / Tag 模型天然承载"技能—状态—取消规则"，弹反窗口可建模为带时长的能力状态；
- 固定 60/120Hz 逻辑帧让判定结果与帧率无关，弹反窗口以帧为单位精确配置；
- 判定与表现解耦：动画负责"看起来如何"，帧数据负责"手里感觉如何"，二者独立迭代。

## 3. 机甲动作帧管线

不做纯逐帧，而是**"动捕基础姿态 + Control Rig 程序化机甲化 + 关键帧精修"的混合管线**。

```text
Maya/Blender 低模硬表面 + 分段骨骼绑定
        ↓
动捕只采基础重心与挥击姿态
        ↓
IK Rig + Motion Warping + 程序化二级运动
        ↓
推进器抖动 / 受击抖动 / 镜头震动 / hitstop
        ↓
机甲重量感
```

### 3.1 数据驱动帧窗口

每个动作通过 **DataAsset** 配置：

| 字段 | 含义 |
|---|---|
| `startup` | 起手帧 |
| `active` | 判定生效帧 |
| `recovery` | 收招硬直帧 |
| `parryWindow` | 弹反窗口 |
| `armor` | 霸体等级 |
| `cancelWindow` | 取消窗口 |
| `hitstop` | 命中停顿 |

**动画负责表现，帧数据负责手感和规则。** 后续新增机甲和武器无需重做管线，只需复用模板 + 调帧数据。

## 4. 最高预算分配（16–20 周，8–10 人核心团队 + 外包）

| 方向 | 占比 | 说明 |
|---|---|---|
| 战斗研发与调参工具 | ~35% | 判定、弹反、取消、帧步进/回放工具链 |
| 动画/绑定/动捕/硬表面 | ~25% | 混合动画管线、机甲重量感 |
| 美术特效与场景 | ~20% | Houdini/Substance 资产、战场环境 |
| 音频/QA/云端试玩/性能优化 | ~20% | Wwise 分层、帧率与串流优化 |

### 4.1 交付物

1. **一台机甲对一台机甲的完整弹反僵直垂直切片**；
2. **可帧步进调试的战斗工具链**（判定盒可视化、输入回放）；
3. **可回放战斗日志**；
4. **云端试玩链接**（Pixel Streaming）。

## 5. 当前原型与愿景的关系

| 维度 | 当前原型（本仓库） | 完整愿景（本文档） |
|---|---|---|
| 目标 | 对齐概念、肯定价值、快速演示 | 可对外评审的 PC 级垂直切片 |
| 形态 | 单文件 HTML 交互演示 + 文档 + C++ 骨架 | UE5 主管线 + Pixel Streaming 试玩 |
| 战斗 | 回合制数值演算简化版 | 帧级判定、弹反、僵直、hitstop |
| 动画 | SVG 示意图 | 动捕 + Control Rig 混合管线 |
| 资产 | 程序化绘制 | Houdini + Substance 硬表面 |
| 扩展点 | 数据驱动（Python 单一数据源） | DataAsset 帧数据（同一理念） |

**两者共享同一设计内核**：数据驱动、判定与表现解耦、可扩展管线。当前原型验证方向与价值，完整愿景承接预算落地。

---

## 6. 风险与应对

- **弹反手感难调** → 用帧步进工具 + 判定盒可视化 + 输入回放，把"玄学手感"变成可量化调参；
- **动捕转机甲失真** → Control Rig 程序化二次运动 + 关键帧精修兜底；
- **Pixel Streaming 延迟** → 云端做轻量试玩，桌面版保留高保真评审；
- **管线前期投入大** → 首台机甲跑通完整管线后，后续机甲复用模板，边际成本递减。
